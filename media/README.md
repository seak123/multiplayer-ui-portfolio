# Gameplay media

Four actual gameplay screenshots are now included. See the [gallery and English captions](../README.md#gameplay-footage-and-screenshots) and [source notes / translated UI labels](SCREENSHOTS.md). The capture plan below is retained for future additions, especially a continuous interaction clip. Engineering diagrams elsewhere describe relationships only.

## Capture / source plan

### 01 — Full team panel

Show the activity target, team members and invitation sources. Prefer a clear, readable crop of the interface while retaining enough game context to understand where it appears.

Caption template: “Team setup and invitation flow, showing [specific state] and the available next action.”

### 02 — Leader and member actions

Show the same flow from leader and member perspectives, or a short transition through unready → ready → all-ready. Explain what action changes, not just how the button looks.

Caption template: “The available action follows role and team readiness. This frame shows [state]; the next action is [action].”

### 03 — Minimise and restore

A 15–30 second clip is preferable: start with the full panel, minimise, continue playing with the HUD status visible, then restore the controls. This most directly demonstrates user-flow thinking.

Caption template: “The compact HUD preserves activity/status awareness while the player returns to gameplay. Restoring the panel reads the current team state.”

### 04 — Contextual support

Show the world support interaction, recommendation/search results and the invite/waiting state. Where possible, include one unavailable player state to show that controls reflect eligibility rather than only appearance.

Caption template: “A support context selects player actions inside the existing multiplayer browsing interface. Pending, busy and offline states have different feedback.”

## How to add files

Use filenames such as `01-team-panel.png`, `02-ready-states.png`, `03-minimise-restore.mp4`, `04-support-list.png` in this directory. Add only the files actually obtained; these are planned names, not broken image links.

For each asset, record:

- Source link or that it is a permitted personal capture, and the video's timestamp if relevant.
- Date/version if known; otherwise state that it is unknown.
- The interaction it proves and any difference from the source snapshot.
- The relevant feature and footage/art credit.
- Any necessary privacy edits: player identifiers/chat and internal diagnostic information should not be exposed.

Public availability is not automatically a licence to reupload someone else's footage. An attributed link and timestamp may be preferable. Once suitable assets are available, place the strongest still and the flow clip in the root README's existing media section.
